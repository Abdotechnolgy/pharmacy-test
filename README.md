# صيدلية الدكتور سالم أحمد فؤاد — Landing Page + متجر (v2)

موقع فاخر ومتكامل لصيدلية الدكتور سالم أحمد فؤاد، مبني بـ Next.js (App Router) و Tailwind CSS و lucide-react.

## ✨ الجديد في النسخة دي
- **سلة شراء حقيقية**: تضيف منتجات، تتحكم في الكمية، والسلة بتتحفظ في المتصفح حتى لو قفلت الصفحة.
- **صفحة إتمام طلب (Checkout)**: بيانات العميل + طريقة الدفع (دفع عند الاستلام / تحويل يدوي) + إرسال الطلب كامل عبر واتساب برسالة منظمة فيها كل المنتجات والإجمالي.
- **صفحة تفصيلية لكل منتج** (`/product/[id]`) بعنوان ووصف SEO خاص بيها، ومنتجات مشابهة.
- **مدونة صحية** (`/blog`) فيها ٣ مقالات جاهزة، وكل مقال له صفحة ورابط وSEO مستقل.
- **لوحة تحكم إدارية** (`/admin`) محمية بكلمة سر — تقدر تضيف/تعدّل/تحذف منتجات من واجهة بسيطة بدون ما تفتح الكود.
- **Sitemap و robots.txt تلقائيين** يشملوا كل المنتجات والمقالات.
- **بيانات Schema.org (JSON-LD)** لنوع "Pharmacy" — بتساعد جوجل يفهم الموقع كصيدلية حقيقية بعنوان ورقم تليفون.

## 🚀 التشغيل محليًا
```bash
npm install
npm run dev
```
افتح `http://localhost:3000`

## 🗄️ ربط قاعدة بيانات حقيقية (Supabase) — مهم جدًا

المشروع متصل بـ **Supabase** (Postgres + Auth + Storage حقيقيين) بدل localStorage.
كل البيانات (منتجات، تصنيفات، عروض، خدمات، إعدادات، طلبات، عملاء، مدونة) متزامنة على كل الأجهزة،
ولوحة التحكم محمية بتسجيل دخول حقيقي (إيميل + كلمة سر عن طريق Supabase Auth).

### خطوة ١ — شغّل الـ SQL (مرتين، بالترتيب، مرة واحدة بس كل واحد)

**أولًا** `supabase/schema.sql`:
1. افتح مشروعك في [supabase.com/dashboard](https://supabase.com/dashboard)
2. **SQL Editor** → **New query** → الصق محتوى `supabase/schema.sql` كامل → **Run**
3. لو ظهرت "Success" يبقى تمام

**ثانيًا** `supabase/schema-v2.sql` (إضافي وآمن — بيضيف من غير ما يمسح حاجة):
1. **New query** تانية → الصق محتوى `supabase/schema-v2.sql` كامل → **Run**
2. ده بيضيف: ربط `products.category_id` الحقيقي بالتصنيفات، جداول `customers` و`orders` و`order_items` و`blog_posts` و`user_roles`، سياسات RLS، وBuckets تخزين الصور.

⚠️ **متشغّلش `schema.sql` تاني** بعد إضافة بيانات حقيقية — هيمسح كل حاجة ويرجع للبذرة الأصلية.
`schema-v2.sql` آمن يتشغّل أكتر من مرة (مبيكررش الجداول أو البيانات).

### خطوة ٢ — أنشئ حساب الأدمن بتاعك (لازم، من غيره مش هتقدر تدخل لوحة التحكم)
1. **Authentication** → **Users** → **Add user** → حط إيميلك وكلمة سر (فعّل "Auto Confirm User")
2. من **SQL Editor**، شغّل الاستعلام ده (غيّر الإيميل لإيميلك اللي سجّلته):
```sql
insert into user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'your-email@example.com';
```
3. جرّب تدخل `/admin/login` بنفس الإيميل وكلمة السر

### خطوة ٣ — تأكد من `.env.local`
الملف موجود بالفعل وفيه بياناتك:
```
NEXT_PUBLIC_SUPABASE_URL=https://qmbqsdffjzxhobteddlo.supabase.co
SUPABASE_SECRET_KEY=sb_secret_...
```
⚠️ **الملف ده متضاف لـ `.gitignore` عمدًا — أبدًا متترفعش لأي GitHub repo عام.**
لو لقيت الملف ده أو الرابط الأصلي فيه المفتاح موجودين في أي كومِت قديم على GitHub، غيّر
الـ Secret Key فورًا من Supabase Dashboard → Settings → API → Reset.

### خطوة ٤ — شغّل المشروع
```bash
npm install
npm run dev
```
افتح `http://localhost:3000` للموقع، و`/admin/login` للوحة التحكم.

### لو نشرت الموقع على Vercel أو أي استضافة تانية
لازم تضيف نفس الـ environment variables (`NEXT_PUBLIC_SUPABASE_URL` و `SUPABASE_SECRET_KEY`) في إعدادات المشروع على المنصة نفسها.

### إيه اللي اتنقل فعليًا لـ Supabase؟
✅ المنتجات (بربط `category_id` حقيقي)، التصنيفات، العروض (بمنطق تواريخ upcoming/active/expired صحيح)، الخدمات،
إعدادات الموقع، إعداد "أحدث المنتجات"، **الطلبات والعملاء** (الـ Checkout بيحفظ فعليًا في قاعدة البيانات قبل
ما يفتح واتساب)، **المدونة بالكامل**، و**تسجيل دخول الأدمن الحقيقي**.

### صور المنتجات/التصنيفات — Supabase Storage
الـ Buckets (`products`, `categories`, `offers`, `services`, `blog`) اتعملت أوتوماتيك من `schema-v2.sql`،
وفيه API route جاهز (`app/api/upload`) ومكتبة صغيرة (`lib/uploadImage.js`) لرفع الصور بدل الطريقة القديمة
(base64 جوه قاعدة البيانات). **ملحوظة صريحة**: فورمات الأدمن الحالية (منتجات/تصنيفات/عروض/خدمات) لسه بتستخدم
رفع base64 القديم داخليًا — الـ Storage API جاهز ومُختبر إنه بيتبني صح، لكن ربط كل فورم بيه لسه خطوة تالية
لم تنفَّذ بعد، مش هخترع إني عملتها.

### أمان
- **تسجيل دخول حقيقي**: Supabase Auth (إيميل + كلمة سر)، مش كلمة سر مشتركة في الكود. الجلسة متخزنة في httpOnly
  cookie، الفرونت إند مبيشوفش التوكن خالص.
- **حماية على مستويين**: `middleware.js` بيعمل تحويل سريع لو مفيش جلسة، و`app/admin/(protected)/layout.js`
  بيتحقق فعليًا (سيرفر) من صحة الجلسة + إن المستخدم عنده دور "admin" في جدول `user_roles` قبل ما يعرض أي حاجة.
- **RLS مفعّلة على كل الجداول**: مفيش أي policy تسمح لـ anon بالقراءة أو الكتابة في `products`/`categories`/
  `orders`/`customers`/إلخ — الوصول الوحيد عن طريق Service Role Key من السيرفر. `blog_posts` استثناء واحد:
  قراءة عامة للمقالات المنشورة بس.
- الفرونت إند مبيكلمش Supabase مباشرة أبدًا — كل حاجة بتعدي من خلال API Routes (`app/api/*`)، فالـ Service
  Role Key الحساس مبيوصلش لكود المتصفح خالص.


افتح **`data/site.js`**:
```js
export const SITE = {
  phoneNumber: "+201000000000",
  baseUrl: "https://your-domain.com", // دومينك بعد النشر
};
```
(رقم واتساب وباقي الإعدادات بقت تتعدّل من `/admin/settings` مش من الكود.)

## 🔐 لوحة التحكم — `/admin`
- تسجيل الدخول بإيميل وكلمة سر حقيقيين عن طريق Supabase Auth — شوف "خطوة ٢" فوق لإنشاء أول حساب أدمن.
- من اللوحة تقدر تدير: المنتجات، التصنيفات، العروض، الخدمات، الإعدادات، أحدث المنتجات، **الطلبات والعملاء**،
  و**المدونة** — كل حاجة بتتحفظ في Supabase فعليًا وتظهر لكل زوار الموقع من أي جهاز فورًا.
- عايز تضيف أدمن تاني؟ كرر خطوة إنشاء المستخدم + إضافته في `user_roles` بنفس الطريقة.

## 💳 عن الدفع الإلكتروني
صفحة الـ Checkout بتحفظ الطلب في Supabase فعليًا (عميل + طلب + أصناف الطلب) قبل ما تفتح واتساب برسالة الطلب،
وبتدعم "الدفع عند الاستلام" و"التحويل اليدوي (انستاباي/محفظة)". ربط بوابة دفع حقيقية زي **Paymob** أو **Fawry**
ممكن ومتاح، لكنه محتاج حساب تاجر معتمد من البوابة نفسها ومفاتيح API، وده شيء لازم تسجّله إنت كصاحب النشاط أولاً.
لو جهّزت الحساب، تعالى قولّي وهنربطه بسهولة.

## 🌍 عن نشر الموقع على دومين حقيقي
الطريقة الأسهل والأسرع لموقع Next.js زي ده هي **Vercel** (مجانية للمشاريع الصغيرة):
1. ارفع الفولدر على GitHub (repo جديد).
2. سجّل دخول على vercel.com بحساب GitHub.
3. اختر "Import Project" واختر الـ repo.
4. Vercel هيكتشف إنه Next.js تلقائيًا ويبنيه وينشره على رابط `.vercel.app` مجاني.
5. من إعدادات المشروع في Vercel، تقدر تربط دومين حقيقي اشتريته (من Namecheap أو GoDaddy مثلاً) في ثواني.

ملحوظة: النشر الفعلي محتاج حساب Vercel وGitHub بتاعك إنت، فمش حاجة أقدر أعملها من هنا، لكن الخطوات فوق كافية إنك تعملها بنفسك في أقل من ربع ساعة.

# 🏥 التحديث الثالث (v3): Pharmacy Management Dashboard + نظام العروض

## ✨ إيه الجديد

### لوحة تحكم كاملة بدل صفحة واحدة
`/admin` بقت Dashboard حقيقية بـ Sidebar responsive، مقسّمة لصفحات:
- `/admin` — الرئيسية: إحصائيات حقيقية، إجراءات سريعة، معاينة العروض النشطة
- `/admin/products` — إدارة المنتجات (مربوطة بـ `category_id` حقيقي)
- `/admin/offers` — إدارة العروض (upcoming/active/expired تلقائيًا حسب التاريخ)
- `/admin/orders` — **لوحة طلبات حقيقية** (تفاصيل العميل، الأصناف، تغيير الحالة) — متصلة بـ Supabase فعليًا
- `/admin/categories` — عرض التصنيفات وعدد المنتجات في كل واحد (بيانات حقيقية محسوبة)
- `/admin/customers` — **قائمة عملاء حقيقية** بتتكوّن تلقائيًا من الطلبات، مع سجل طلبات كل عميل
- `/admin/blog` — إدارة مقالات حقيقية (نشر/إلغاء نشر) متصلة بـ Supabase
- `/admin/settings` — بيانات الصيدلية وحساب لوحة التحكم (Supabase Auth)

كل الصفحات فيها toast notifications عند الإضافة/التعديل/الحذف، وconfirmation dialog قبل أي حذف.

### نظام العروض (كامل)
- صفحة عامة `/offers` بتعرض كل العرض النشطة
- قسم "عروض مميزة" في الصفحة الرئيسية قبل الفوتر (بيختفي تلقائيًا لو مفيش عروض نشطة)
- كل عرض مرتبط بمنتج موجود فعليًا (مش بيانات مكررة)
- خصم % بيتحسب تلقائيًا من السعرين
- العرض بيتحول لـ"منتهي" تلقائيًا لو تاريخ النهاية فات
- العروض شغالة مع الكارت والـ Checkout بالكامل — السعر المخفض هو اللي بيتبعت في رسالة واتساب

## ⚠️ حاجات مهمة تعرفها

**الطلبات والمبيعات والعملاء مش متتبعة فعليًا.** الموقع بيبعت كل طلب لواتساب مباشرة، ومفيش قاعدة بيانات
تحفظ نسخة منه. صفحة `/admin/orders` مصممة بالكامل وجاهزة تستقبل بيانات حقيقية فورًا بمجرد ما نربط
المشروع بـ **Supabase** — مفيش أرقام وهمية اتحطت في أي مكان.

**كلمة سر الأدمن** بقت متخفية في `/admin/settings` — لسه بتتغير من `data/site.js` زي الأول، ومفيش نظام
Authentication حقيقي (توضيح كامل موجود في صفحة الإعدادات نفسها).
